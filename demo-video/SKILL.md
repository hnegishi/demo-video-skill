# Demo Video

ソフトウェアの動きを短い動画で見せるためのスキル。対象に応じて 3 つの作り方を使い分け、最後に必ず中身を検証してから渡す。

## 1. 作り方を選ぶ

| デモ対象 | 作り方 | 読む手順書 |
|---|---|---|
| ブラウザで動く UI がある（URL、`npm run dev` で立ち上がるアプリ、HTML ファイル） | Playwright で操作して録画 | `references/web.md` |
| CLI、ターミナルでのコマンド操作、TUI | VHS の `.tape` で録画 | `references/cli.md` |
| 見せる UI がない（ライブラリ、API、内部処理、アーキテクチャ、データの流れ） | HTML/CSS アニメーションを作って録画 | `references/motion.md` |

判断に迷う例:
- UI はあるが、見せたいのが裏側の処理（キャッシュの効き方など）なら motion。
- CLI が TUI を立ち上げるなら cli（VHS は TUI も録れる）。
- Web アプリを CLI から起動する手順込みで見せたいなら、cli と web を別々に録って `scripts/concat.sh` でつなぐ。

選んだ手順書だけを読む。3 本すべてを読む必要はない。

## 2. 作る前に決めること

ユーザーが指定しなければ、次のデフォルトで進めて、最後の報告で何を選んだかを書く。

- **長さ**: 15〜60 秒。1 本で伝える要点は 1〜3 個。長くなるなら動画を分ける方が見てもらえる。
- **解像度**: 1280x720。README 用の GIF なら幅 960 に縮小。
- **形式**: MP4（H.264）。GIF は「README/PR/Slack に貼る」と言われたとき、または頼まれたときに `scripts/to_gif.sh` で追加する。
- **テロップ**: 操作の意図が画面だけで伝わらないときに短く入れる（1 行 20 文字前後）。描き方は「3. 注釈と演出」を参照。ナレーション音声と BGM は頼まれない限り付けない。
- **言語**: テロップや画面上のテキストはユーザーの言語に合わせる。

最初に 3〜6 行の台本（シーンごとに「何を見せるか」と秒数）をメモしてから録画する。台本があると、待ち時間の不足や冗長なシーンに録画前に気づける。

## 3. 注釈と演出（テロップ・タイトル・強調枠・吹き出し・クリックエフェクト・ズーム）

注釈と演出は、どの方式でも **Pillow で描いて録画後に焼き込む**。録画する画面（ページや端末）には描かない。描画は `scripts/annotate.py` がまとめて受け持ち、フォントは `scripts/jpfont.py` が OS に最初から入っている日本語フォントを選ぶ（macOS: ヒラギノ角ゴシック、Windows: 游ゴシック → メイリオ、Linux: Noto Sans CJK JP など）。

こうする理由:
- 見た目が方式によらずそろう（Web 録画でも CLI でもモーション動画でも同じテロップ）
- 画面側のフォントや CSS に左右されず、日本語が確実に表示される。日本語フォントが見つからなければエラーで止まり、豆腐（□）のまま出力されることはない
- 時刻と文言が `*.annotations.json` に残るので、録り直さずにテロップだけ直せる
- 実際の映像を見て置き場所と色を決められる（下記）

### 読みやすさは `annotate.py` が自動で守る

- **背景色が映像に溶け込まない。** 注釈ごとに、置く場所の映像の明るさを測り、明るい映像には暗い下地、暗い映像（ターミナルなど）には明るい下地を使う。
- **対象やコンテンツに重ならない。** テロップ・吹き出し・ラベルは、表示期間中の実際のフレームで文字や UI がない場所（周囲 24px の余白込み）を探して置く。強調している対象そのもの、ほかの注釈とも重ならない。
  - テロップの置き場所がどこにもない場合（ズーム中で画面が埋まっているなど）は、その間だけ映像を少し縮めて上に寄せ、下にできた帯にテロップを入れる。
  - 強調枠のラベルを置く場所がない場合は、離れた空き場所に吹き出しとして置き、線で枠とつなぐ。
  - それでも重なるときは `[annotate] warning: ...` が出る。録画側で余白を作る（ウィンドウを広げる、出力を短くする、ページに余白を足す）。
- **ズーム中もテロップの場所を空ける。** ズームの範囲は、対象が画面下のテロップ帯にかからないように決まる。

### ズームとクリックエフェクトを使う場面

使うかどうかは内容に合わせて判断する。
- **クリックエフェクト**（クリック位置から細い白い輪が広がって消える。塗りがないので押した要素を隠さない）：web では `demo.click()` / `demo.type()` で自動的に付く。操作の場所を示したいときに役立つ。不要なクリックには `{effect: false}` を付けて出さない。
- **ズームイン**：小さな UI（入力欄、ボタン、件数表示）や、ターミナル出力の一部を読ませたいときに使う。1280x720 に縮小すると読めない文字は、ズームしないと伝わらない。
- **ズームアウト**：操作の結果を全体で見せたいときや、次の操作対象がズーム範囲の外にあるときに使う。
- ズームは 1 本の動画で 2〜4 回までにする。頻繁に寄ったり引いたりすると酔う。寄ったら 1.5 秒以上は止めて読ませる。拡大率は 2.5 倍程度まで（それ以上は画質が荒れる）。

| 方式 | 指定方法 | 詳細 |
|---|---|---|
| web | シナリオで `demo.caption()` / `title()` / `box()` / `callout()` / `zoomTo()` / `zoomOut()` を呼ぶ。クリックエフェクトは `click()` で自動。時刻と要素の座標は自動で記録される | `references/web.md` |
| cli | `.tape` に `# @caption` / `@title` / `@box` / `@callout` / `@zoom` などの印を書き、`tape_annotations.py --burn` で焼き込む。座標は `inspect_video.py --grid` で読み取る | `references/cli.md` |
| motion | HTML の各シーンに `data-caption` を書く。強調やズームは HTML 自体のアニメーションで表現してよい。必要なら `window.__demoAnnotations` に注釈を直接書ける | `references/motion.md` |

### 注釈の直し方（録り直さない）

テロップの文言・表示時間・ズーム範囲を直すときは、`*.annotations.json` を編集し、まず `--check` で確かめてから焼き込む。`--check` はエンコードしないので数秒で終わり、配置の警告・帯の通知・読む時間が足りないテロップを表示し、各注釈の表示中の場面を並べた `*.check.png` を書き出す。この画像を Read で見て、問題がなくなってから本番の焼き込みをする。
```bash
python3 <skill>/scripts/annotate.py demo.plain.mp4 demo.annotations.json --check   # 数秒。demo.annotations.check.png を見る
python3 <skill>/scripts/annotate.py demo.plain.mp4 demo.annotations.json demo.mp4  # 本番
```
CLI では `tape_annotations.py demo.tape --burn --check` で同じ確認ができる。

カーソルだけは録画中のページに描く（実際のマウスの動きとフレーム単位で同期させるため）。

## 4. 道具

| 道具 | 用途 | 無いとき |
|---|---|---|
| ffmpeg / ffprobe | 変換・検証（全方式で必須） | `brew install ffmpeg` |
| Python 3 + Pillow | 注釈の描画・検証用の一覧画像 | `python3 -m pip install pillow`（入れる前にユーザーに確認する） |
| 日本語フォント | 注釈 | OS 標準のものを自動で使う。Linux で見つからないときは `fonts-noto-cjk` など（入れる前に確認する）。`DEMO_VIDEO_FONT=/path/to/font` で指定もできる |
| Playwright + Chrome | web / motion | `scripts/record_web.mjs` が初回に `~/.cache/demo-video-skill` へ自動で入れる。ブラウザはインストール済みの Google Chrome を使い、無ければ Playwright の Chromium を使う |
| VHS | cli | `brew install vhs`（入れる前にユーザーに確認する） |

システムへのインストールは副作用なので、無い道具を入れる前にはユーザーに一言確認する。

## 5. 映してはいけないものを避ける

デモ動画は PR、README、Slack などで広く共有される。録画した画面に映ったものは、すべて公開されると考える。
- **録画前に**：本物の認証情報、API キー、トークン、顧客データ、社内の URL やホスト名、ユーザー名やメールアドレスが出る画面や出力を避ける。デモ用のダミーデータとダミーアカウントを使う。
- **CLI**：`env`、`printenv`、`cat .env`、`git config --list`、`history` のように秘密が出やすいコマンドは録らない。準備でシェル履歴を切る（`references/cli.md`）。
- **Web**：ログイン済みのブラウザプロファイルは使わない（`record_web.mjs` は毎回まっさらなプロファイルで起動する）。通知、ブックマーク、別タブは映らないが、ページ内に出るユーザー名やアバターには注意する。
- **録画後に**：次の検証でフレーム一覧を見るときに、これらが映っていないかも確認する。映っていたら、ダミーデータに差し替えて録り直す。ぼかしで隠すより確実。

## 6. 検証する（省略しない）

Claude は動画を再生できない。録画が真っ黒、途中で止まっている、ログイン画面のまま、エラー画面が映っている、といった失敗は、検証しないと気づけずに「完成」と報告してしまう。完成したファイルごとに必ず次を実行する。

```bash
python3 <skill>/scripts/inspect_video.py out/demo.mp4            # 等間隔に 8 コマ
python3 <skill>/scripts/inspect_video.py out/demo.mp4 --at 1.2,4,7.5   # 指定した時刻のコマ
```

出力される尺・解像度・平均輝度を確認し、生成された `<動画ファイル名>.contact.png`（時刻入りのフレーム一覧）を Read で開いて目で見る。注釈を入れたなら、`--at` で各注釈の表示中の時刻を指定して、出るべき場面で出ているかも確かめる。確認すること:

- 台本のシーンが順番どおりに映っているか
- 文字が読める大きさか（小さすぎるなら拡大して録り直す）
- エラー、空白画面、読み込み中の画面が長く映っていないか
- 尺が台本と大きくずれていないか
- テロップが操作や場面と合ったタイミングで出ていて、大事な部分を隠していないか。焼き込み時に `[annotate] warning`（重なりが避けられなかった）や `[annotate] band`（映像を縮めて帯を作った）が出ていたら、その時刻を `--at` で必ず見る。帯が何度も出るなら、録画側に余白を作って録り直す
- ズームした場面で、見せたいものが画面内に収まり、カーソルの動きが画面外に出ていないか
- 認証情報、個人情報、社内情報が映っていないか（前節）

問題があれば直して録り直す。2〜3 回で直らないときは、状況をユーザーに説明して相談する。

## 7. 仕上げと報告

- 成果物は、ユーザーが指定した場所、またはリポジトリ内の分かりやすい場所（例: `docs/demo/`）に置く。録画用スクリプト（シナリオ `.mjs`、`.tape`、motion 用 HTML）と `*.annotations.json`、注釈なしの `*.plain.mp4` も成果物の隣に残す。あとで UI が変わったときに録り直せるようにするため。
- GIF が必要なら `bash <skill>/scripts/to_gif.sh in.mp4 out.gif [幅] [fps]`。GIF が 10MB を超えたら幅か fps を下げる（GitHub の README では大きい GIF が表示されにくい）。
- 報告には次を含める: 出力ファイルのパス、尺と解像度、選んだ作り方とその理由、台本の要約、録り直し用スクリプトの場所、`[annotate]` の警告や帯が出ていた場合はその対処。

## scripts/

- `record_web.mjs` — Playwright 録画。シナリオ（`.mjs`）または HTML ファイルを受け取り、MP4 を出力する。止まった画面でも録画が途切れないようにする処理、カーソルの表示、冒頭の空白のトリム（冒頭の同期用フラッシュで注釈の時刻を映像に合わせる）、注釈の記録と焼き込みを内蔵。使い方は `references/web.md`。
- `annotate.py` — `annotations.json` の注釈と演出（caption / title / box / callout / click / zoom）を Pillow で描いて動画に焼き込む。置き場所と色は映像を見て自動で決める。
- `jpfont.py` — OS 標準の日本語フォントを探す（`python3 jpfont.py` で何が使われるか表示）。
- `tape_annotations.py` — `.tape` の `# @caption` などの印から `annotations.json` を作り、焼き込む。
- `inspect_video.py` — 尺・解像度・コーデック・平均輝度の表示と、時刻入りのフレーム一覧画像の生成。`--grid` で座標読み取り用の方眼付き画像も出す。
- `to_gif.sh` — パレット生成付きの高品質 GIF 変換。
- `concat.sh` — 複数の動画を解像度をそろえてつなぐ。
